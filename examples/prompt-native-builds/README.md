# Prompt-native builds: selected examples

This collection pairs one Scissortail demonstration with two completed VoidCode source builds. They are distinct prompt-native dialects and products; these files are supplied as readable source examples, not as claims of deterministic execution or benchmark results.

## Selected builds

| File | Edition and provenance | Build/runtime route | Limits |
|---|---|---|---|
| [`HorizonMini-1.1-VoidCode.txt`](HorizonMini-1.1-VoidCode.txt) | HorizonMini completed edition 1.1; source edition SHA-256 `165534bda10274eab7a678a12e8ce0b191530a58935e9ac654489ba97b6b6702`. Prairie Labs source. | [General Simulation Company Prairie portal](https://gensim.co/prairie/); hosted use is access/code gated. | Prompt-native VoidCode source. Model adherence is not deterministic; this is not a Python/JavaScript runtime and grants no external tool access. The portal is not a public source download. |
| [`Kings-Dilemma-Original-Complete-VoidCode.txt`](Kings-Dilemma-Original-Complete-VoidCode.txt) | Original King’s Dilemma all-decks simulation, standalone v3.0 VoidCode export; assembled from the preserved original package; 708 authored cards across 15 populated decks. This is the OG/original edition, not Baldwin. | [Prairie Engine](https://prairieengine.com/) | Prompt-native engine/schema with host primitives (including RNG and clock facilities); the source marks execution as host-dependent. It is not a standalone JavaScript application. The live arcade build is a distinct release and is not represented as byte-identical to this export. |
